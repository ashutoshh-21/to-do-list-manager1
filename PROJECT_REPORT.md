## 1. TITLE

**AI-Powered ToDo List Manager: Applying Machine Learning to CLI Task Management**

---

## 2. INTRODUCTION

This project presents a Command-Line Interface (CLI) based ToDo List Manager that goes beyond standard CRUD operations by embedding six AI/ML algorithms — all implemented from scratch in pure Python — directly into the task management workflow.

The application is built on Python's standard library with SQLite as its persistence layer. When a user adds a task, a Naïve Bayes classifier trained on their past tasks automatically predicts the appropriate priority level, while a TF-IDF cosine similarity engine suggests the most relevant category. A K-Means clustering engine groups tasks visually, a Z-Score anomaly detector flags unusual overdue patterns, a Linear Regression model forecasts upcoming workload, and an urgency scoring recommender ranks what to work on first.

Every algorithm is self-contained and implemented from mathematical first principles — no scikit-learn, no pandas, no NumPy — demonstrating deep understanding of the concepts taught in this course rather than simply calling library functions.

## 11. ALGORITHM DEVELOPMENT

---

### Algorithm 1: Naïve Bayes Classifier (Priority Prediction)

**Mathematical Foundation:**
```
P(priority | words) ∝ P(priority) × Π P(word | priority)
```

Using log space for numerical stability:
```
log_score(c) = log P(c) + Σ log P(word_i | c)
```

Laplace smoothing (add-1):
```
P(word | c) = (count(word, c) + 1) / (total_words_in_c + V + 1)
```
where V = vocabulary size.

Softmax for final probabilities:
```
P(c) = exp(score_c) / Σ exp(score_j)
```

**Implementation steps:**
```
TRAIN:
  For each task:
    Tokenize(title + description) → word list
    class_counts[priority] += 1
    For each word: word_counts[priority][word] += 1
    Add words to vocabulary

PREDICT(title, description):
  tokens = Tokenize(title + description)
  For each class c in {high, medium, low}:
    log_score[c] = log((class_counts[c]+1)/(total+3))
    For each token t:
      log_score[c] += log((word_counts[c][t]+1)/(total_c+V+1))
  Apply softmax → probabilities
  Return argmax(probabilities)
```

---

### Algorithm 2: TF-IDF + Cosine Similarity (Category Classification)

**TF (Term Frequency):**
```
TF(t, d) = count(t in d) / len(d)
```

**IDF (Inverse Document Frequency):**
```
IDF(t) = log(N / df(t) + 1) + 1
```

**TF-IDF:**
```
TF-IDF(t, d) = TF(t, d) × IDF(t)
```

**Category centroid:**
```
centroid(cat) = (1/|docs_cat|) × Σ tfidf_vec(doc)
```

**Cosine Similarity:**
```
sim(A, B) = (A · B) / (|A| × |B|)
```

Classify new task to category with maximum cosine similarity to its centroid.

---

### Algorithm 3: K-Means Clustering

**Feature vector per task:**
```
x = [priority/3, (days_to_due+30)/60, completed, title_length/100]
```

**Euclidean distance:**
```
dist(a, b) = √Σ(ai - bi)²
```

**K-Means iterations:**
```
INIT: Select K random points as centroids
REPEAT:
  For each point xi:
    label[i] = argmin_k dist(xi, centroid_k)
  For each cluster k:
    centroid_k = mean of {xi : label[i] = k}
UNTIL centroids unchanged OR max_iter reached
```

---

### Algorithm 4: Z-Score Anomaly Detection

```
μ = Σxi / N
σ = √(Σ(xi - μ)² / N)
z_score(xi) = (xi - μ) / σ
```

Flag as anomaly if |z_score| > threshold (set to 1.5).

Applied to:
- Distribution of overdue days across pending tasks
- Distribution of daily task completion counts

---

### Algorithm 5: Linear Regression — OLS

Data: xi = day index, yi = tasks created on day i

**Slope:**
```
w = Σ(xi - x̄)(yi - ȳ) / Σ(xi - x̄)²
```

**Intercept:**
```
b = ȳ - w × x̄
```

**Prediction for day x:**
```
ŷ = w × x + b
```

Predict for days n+1 to n+7 where n = number of historical days.

---

### Algorithm 6: Urgency Scoring

```
urgency_score(task) = priority_weight / (days_remaining + 1)

priority_weight:  high=3, medium=2, low=1
days_remaining:   max(0, due_date - today)  [default 7 if no due date]
```

Higher score = needs more immediate attention.
Top-5 tasks by urgency score are shown with contextual advice.

## 20. LIMITATION / CONSTRAINTS

1. **Cold start problem** — AI predictions are weak until the user has added 10+ tasks; NB and TF-IDF need training data
2. **Single-user, local only** — SQLite database is not designed for multi-user or cloud access
3. **No notifications** — no reminders for upcoming due dates
4. **No recurring tasks** — does not support repeating tasks
5. **K-Means non-determinism** — random centroid initialisation means cluster assignments may vary between runs (mitigated with a fixed seed)
6. **Linear regression assumes trend** — forecasting breaks down if the user's task creation rate is highly variable
7. **No GUI** — terminal-only; requires ANSI-compatible terminal for color output
